# 在线刷题网站 · 需求说明

> 我在做一个刷题网站（自己用，也给同学用）。下面是我整理的需求。**这是最低要求，不是上限**——真实用户还需要什么，我会陆续补充；你有建议先提出来，我确认后再动手。

配套材料（都在项目里）：

- `ref\题库\` —— 两套题库：Java 219 题；Web 120 题、6 个章节。Markdown 原始格式。
- `ref\原型\index.html` —— 一个很基础的参考原型（只有最简实现，题目是示例数据）。

## 一、核心使用流程（必须完整、顺畅）

- 打开网站，看到有几个题库可以挑；挑一套进入答题页——题干和全部选项都在。
- 选答案 → 点提交 → **立刻知道对错**；答错时能看到正确答案和解析。
- 做完一题点「下一题」；想回去看，点「上一题」。
- 随时能看到：做到第几题、已经答对几道。
- 做到最后一题，交卷 → 结果页：答对几道、错在哪几道。

**底线一条：同一道题重复点几次提交，成绩不能变。**（手抖多点两下「提交」，正确率不该从 80% 跳到 120%。）

## 二、题库数据

- 原始题库是 Markdown，**项目里用什么格式存由你决定**（JSON、JS 数组、……都行）；把 Markdown 转成项目数据格式，是你工作的一部分。
- 三条约定：**① 不要自己编写新题目；② 不要修改题目内容（题干、选项、答案）；③ 题库不保证每一条都完全规范**——你发现不规范的地方，先报告给我，我来决定怎么处理。
- 题量对账：Java 219 题、Web 120 题。转换完成后对一下数。

## 三、真实使用场景（希望都能覆盖）

> 下面九条是举例，不是全部。你能想到别的真实使用问题，先告诉我，我来决定做不做。

- 熄灯的宿舍，躺床上刷五分钟 —— 低亮度下也能舒服地用；
- 手机上、地铁里，一只手扶着栏杆 —— 单手能操作；
- 一套两百多题，今天只想刷第一章 —— 能按范围 / 章节刷；
- 做到第 80 题被叫去开会，回来接着做 —— 进度保存、断点续做；
- 做完一遍，只想再看那几道错的 —— 错题回顾 / 重做；
- 考前想把几道重点题标出来 —— 标记 / 收藏；
- 想跟室友比比谁正确率高 —— 成绩记录 / 分享；
- 刷完停下来，盯着这个页面看十秒 —— 好不好看？见下一节；
- 找个同学用一次，我在旁边看着、什么都别说 —— 可用性检验。

## 四、关于界面（重要）

**你没有眼睛，我看得见。** 你能写出一堆 CSS，但看不出页面丑不丑、挤不挤、对没对齐。所以：

- 你做完不要对我说「完成了、很好看」；请告诉我：改了哪些文件、我该打开哪里、重点看什么。
- 我会真的打开页面看，把发现的问题用文字描述给你（例如「按钮的阴影方向反了」「这两行挤在一起」），你按我说的改。
- 视觉判断和方向由我定。整体风格我有明确要求（新拟物 / Soft UI），样式规范会作为单独的提示词发给你。

## 五、我在意的代码质量

- **同一个事实只写一处**：改一条规则不需要满项目翻。
- **同一道题在不同页面（答题页 / 错题本 / 结果页）的显示与判定必须一致。**
- 删掉的功能清干净，不留没用的按钮和死代码。
- 别人拿到项目，能按 README 跑起来。
- **不要把题库、判题、页面全塞进同一个几百行的文件**，按职责拆清楚。
- 纯静态优先：双击 `index.html` 就能用；无构建步骤、不依赖联网资源（CDN 也不要）。

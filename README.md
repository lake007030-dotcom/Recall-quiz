# Recall（纯静态刷题站）

> 刷题，安静一点。

Recall 是我做的一个小型刷题站：两套题库（Java 219 题、Web 120 题 6 章），选答案 → 提交 → 立刻判对错，答错给正确答案与解析，交卷出结果页；进度存在本机浏览器里，双击 `index.html` 就能用。

没有构建步骤、没有 `npm install`、不联网（无 CDN、无外部字体；可选的服务端也只在本机）。文件通过 `<script src>` 相对路径加载，所以不能把 HTML 单独拷走，要整个文件夹一起移动。

## 功能清单

一句话一个功能：

| 功能 | 说明 |
| --- | --- |
| 题库选择 | 首页两套题库卡片，点进去先选范围再开始 |
| 范围（全部 / 章节 / 随机 N） | 整库、按章节多选、随机抽题——三个选项各配一枚 20px 内联 SVG（layers / book-open / shuffle），选中时图标跟着文字变强调色；快捷档 10 / 20 / 50，也可以自己填 1–题库题数；随机只抽一次，刷新不重抽 |
| 答题与即时判分 | 选完提交立刻判对错，答错给正确答案与解析，支持单选 / 多选 / 判断 |
| 防重复提交（幂等） | 判分只认「已提交且判对」的题号集合，同一题重复判定结果不变；提交后按钮变「已提交」并禁用 |
| 提交后修改答案（交卷前） | 已提交的题在状态行右侧给「修改答案」，点了解锁重选、主按钮回到「提交」，再提交重新判定，统计跟着变；交卷后只读，不再有这个入口 |
| 追加需求「再练一遍没做对的」 | 交卷后按本轮判错的题组一轮独立的新练习，可递归重练 |
| 练习记录（回看与继续） | 每题库一条记录入口：已完成的一轮只读回看，没做完的接着做 |
| 错题本（跨轮聚合） | 按题库汇总所有轮里「已提交且判错」的题：同一道题多轮错只出现一次，记错误次数与最近出错时间；按章节 → 题号分组，行只读 |
| 错题练习 | 用错题本里的题另开一轮练习（复用普通练习的作答 / 交卷 / 出结果 / 再练一遍），原轮记录不受影响 |
| 标记重点题（收藏） | 题目卡片右上角星标，题目级收藏、普通轮 / 重练轮 / 收藏练习共用同一颗星 |
| 收藏练习 | 用某题库收藏的题另开一轮练习，题序取题库原序 |
| 题目纠错反馈与维护日志 | 每题可就地反馈（自动带上题库/题号/题型/题干摘要），本机反馈箱一键复制；维护日志按日期列出修正 |
| 服务端（可选增强） | 起 `node server\server.mjs`（默认 8080）后反馈写入本机 SQLite，`/admin` 可按题库 / 类型 / 状态筛选、标记已处理 / 忽略、导出 CSV；探不到服务端就静默退回纯静态，功能不变 |
| 主题（跟随系统 / 亮色 / 暗色） | 顶栏点开三选一菜单：跟随系统（默认，监听 `prefers-color-scheme` 实时切） / 亮色 / 暗色；选择记在本机 `quiz:theme`，刷新保持，`<meta name="theme-color">` 与 `color-scheme` 跟着解析后的主题走 |

## 运行方式

**① 双击 `index.html`。** 没有构建、没有依赖、没有 CDN，`file://` 下就是完整功能（Chrome / Edge / Firefox 均可）。题库是打包进 `js/data/*.js` 的普通脚本，所以不起服务也能跑。

**② 起一个本地静态服务（可选）。**

```bash
python3 -m http.server 8080
# 然后访问 http://localhost:8080
```

只有在想跑 `tools/e2e-narrow.html`（窄视口专项）时必须用这种方式——它靠 `<iframe>` 加载 `index.html` 再量尺寸，`file://` 下 iframe 是跨域（null origin），会抛 `SecurityError: Blocked a frame with origin "null"`。可选的服务端 `node server\server.mjs` 自带静态托管（默认也是 8080），只是跑页面时可以拿它代替 python，两者选一个即可。

**数据从哪来。** `js/data/java.js`、`js/data/web.js` 由 `ref/题库/*.md` 转换而来，是生成物，不要手改；改题请改 `ref/题库/` 下的原始 Markdown，然后重跑转换器（勘误也写在转换器的 ERRATA 表里）。

**两条自测命令**（改数据、改判题后各跑一次）：

```bash
node tools/convert-banks.mjs
node tools/test-judge.mjs
```

## 两种运行模式

**① 纯静态（默认，双击即用）。** 双击 `index.html`，作答、判分、统计、练习记录、反馈箱、主题全套可用；数据（`quiz:*` 那几组 localStorage）只存在这台设备，不联网也能用。反馈的「上报」就是把面板里那段文本复制、贴给维护者。

**② 服务端（可选增强，不装也能用）。** 在项目根目录执行：

```bash
node server\server.mjs
# 默认 http://localhost:8080
```

服务端只做增强、不改站点逻辑：静态托管同一套页面，把提交的反馈写进本机 SQLite，并多一个 `/admin` 管理后台（查看、按题库 / 类型 / 状态筛选、标记已处理或忽略、导出 CSV）。前端打开页面时探测 `GET /api/health`（1.2s 超时）：探到了且提交成功就提示「已上报」，提交失败或探不到就照旧回落本机反馈箱、提示「已记录（仅本设备）」——**不弹任何提示、不挡任何操作，纯静态模式不受影响**。

- **端口 / 数据库**：默认 `8080`，`PORT` 可改；数据库默认 `server/data/recall.db`（WAL），`DB_PATH` 可改，`server/data/` 首次启动自动创建。
- **管理员令牌**：首次启动自动生成到 `server/data/admin-token.txt`（`DB_PATH` 换了就跟数据库同目录），启动日志会打印这个路径；后台地址 `http://localhost:8080/admin`，用令牌登录，会话 2 小时。这个文件相当于后台口令，不要外传。
- **限流与上限**：反馈提交 10 次/分钟/IP，管理员登录 5 次/分钟/IP；请求体上限 64KB，超了回 413。
- **自测**：`node server\smoke.mjs`（随机端口 + 临时库，跑完自动清理，最后一行应为 `SMOKE PASS 23/23`）。

只想本地刷题，双击 `index.html` 就够了；需要把反馈收进库里再看后台时，才起服务端。

## 关键设计

**1. 判分只有一个入口。** 对 / 错 / 未作答 / 数据异常不计分，全部由 `js/core/judge.js` 的单一函数判定；`session.evaluate()` 只是取它的结果，视图层一行判定逻辑都没有。改判分口径只需要动这一个文件，`tools/test-judge.mjs` 的 106 项就是围着它写的。

**2. 答对数由集合派生，所以重复提交天然幂等。** 统计不靠计数器累加，而是每算一次就从「已提交且判对」的题号集合里重新派生（`session.stats()`）。同一题提交十次，只是把同一条作答事实覆盖十次，集合不变，分数就不会变——幂等是数据结构保证的，不是靠「点没点过」的标志位挡住的。e2e 里对同一题连判 5 次、以及「提交按钮已禁用后再点」都断言了 correct / submitted 不变。

**3. 交卷即冻结（轮次快照）。** 交卷时把这一轮冻成快照写进 `quiz:rounds:<题库>`，写入前 `Object.freeze` 深冻结，之后**只追加不修改**。结果页、练习记录的回看读的都是这份冻结的快照，所以「历史的数字」不会被后来的操作改掉。

**4. 范围与重练各走各的键。** 范围（全部 / 章节 / 随机）在「开始」那一刻定成题号列表写进本轮的 `questionIds`，刷新、切题、返回再进都不会重抽；重练轮有自己的进度键 `quiz:practice:<题库>:<原轮 id>`，作答、交卷都发生在那个键上，**碰不到原轮的键**。所以重练一轮不会让原轮的得分、逐题记录、进度发生任何变化（e2e 里有逐字节对照）。

**5. 「没做对」的定义只写一处。** `wrongIds()`：本轮里**已提交且判错**的题才算。选了答案没点提交的不算，没碰过的不算，数据异常题（`scorable: false`）也永远不算。按钮上的计数、重练轮的题号列表都来自这个函数，视图不另算。

**6. 反馈默认走本地。** 纯静态、不联网，所以反馈只存在这台设备的 `quiz:feedback` 里，上报靠「一键复制」那段固定格式的文字，由使用者自己贴给维护者。换来的是零依赖、双击即用、反馈不丢半路；代价是换设备看不到自己提交过的反馈，也没有自动收集。起了可选的服务端（见「两种运行模式」）只是多一条「提交时顺手入库」，本地箱、复制格式与这套取舍都不变。坏数据（不是合法 JSON、版本不符、字段缺失）一律当成空箱，不报错、不白屏。

**7. 悬停反馈三选一。** 全站可点元素的悬停反馈必须是下面三种之一，且矩形尺寸不变、不位移：背景变化（→ `--bg-2` 或 `--accent-soft`）、阴影跨一整档（如 8/16 → 4/8）、主色变亮一档（`--accent` → `--accent-hover`）。文字色变化只能作为附加，不能是唯一反馈——12–13px 下几乎看不出来。禁用态不参与。

## 错题本与错题练习

**入口。** 首页每张题库卡片下面一行三个小按钮：`练习记录（n）` `错题本（n）` `收藏练习（n）`。每个按钮左侧一颗 14px 内联 SVG（时钟 / 书本 / 星形，1.5px 描边跟着字色走）。它是导航型入口，反馈方式与页面底部那两行一致：鼠标移上去浮出 `--bg-2` 淡底色、文字与图标一起从 `--ink-2` 变 `--ink`，阴影再从 4/8 收到 3/6；按下转内凹，底色留着。位置、尺寸、圆角一点不动。n 是这道题库当前的条数，**为 0 时按钮置灰（`opacity:.5`）但保留**、悬停时背景/字色/阴影全都不动，也不带一点反馈（还带一行小字「还没有错题」「还没有标记的题」），不做隐藏——藏起来就没人知道有这个功能了。375px 下三个按钮缩内边距、字号降到 12px，仍排在一行之内，不横向滚动。

**口径（只认一件事：已提交且判错）。** 错题本不新增任何存储，每次现算：把 `quiz:rounds:<题库>` 里所有**已完成**的快照拿出来，对每一轮用 `js/core/judge.js` 重算 `wrongIds()`（与结果页「再练一遍」用的是同一个函数、同一条口径），再把题号并起来去重。具体规则：

- 同一道题在几轮里都错，只出现**一次**，`错 n 次` 是它判错过的轮数；
- 「最近」取这几轮里最晚的那次 `finishedAt`；
- **选了答案但没提交的不算**，**没碰过的不算**，数据异常题（`scorable: false`）永远不算；
- 只列这道题库里还存在的题号（题库换版后残留的题号自动跳过）。

现算的代价是每次进页面扫一遍快照，好处是不用维护第二份数据、也不会和快照对不上。339 道题 × 十几轮的体量下毫无感知。

**列表。** 按 **章节 → 题号** 排序并分组（组标题带本组题数），每行：题号、题型徽标、题干前 40 字、`错 n 次`、`最近 MM-DD HH:mm`。行是**只读**的，不能点进去跳题——错题本的作用是让你看清错在哪儿、然后整批再练一遍，不是当目录用。

**错题练习。** 顶部主按钮 `错题练习（n）`，按下就按错题本的顺序（章节 → 题号）另起一轮：作答、提交、交卷、结果页、「再练一遍没做对的」全都复用普通练习那一套。它在练习记录里显示为「**错题练习**」，与原普通轮并列；**原轮的得分与逐题记录一个字都不会变**（它自己的进度存在独立的键上，见下）。

**存储键。** 错题本本身不占键。错题练习这一轮的进度存在 `quiz:pool:<题库>:wrongbook`（`Round.poolKey()` 生成），交卷快照照常写进 `quiz:rounds:<题库>`，只是多一个可选字段 `origin: 'wrongbook'`——普通轮、重练轮的快照形状完全没变，老快照没有这个字段也照读。

**和「再练一遍没做对的」的区别。** 一句话：**错题本是跨轮的，再练一遍是单轮的。**

| | 题目来源 | 范围 | 什么时候用 |
| --- | --- | --- | --- |
| 错题本 → 错题练习 | `quiz:rounds:<题库>` 里**所有轮**的错误题去重 | 跨轮累积，练完不清空 | 考前集中刷自己常错的题 |
| 结果页 → 再练一遍没做对的 | **当前这一轮**判错的题 | 单轮，只跟这一轮有关 | 刚交完卷，趁热把这轮错的补掉 |

两者都复用同一套练习机制、都在练习记录里单独成条、都不会改原轮数字；区别只在题从哪儿来。练完错题练习，错题本**不会**清空（题目级事实不会因为练过一次就消失）——想让它变短，只能让那些题在后续轮次里答对（而已有的判错事实仍然会把它算进错题本，这也是下一节「如果再给 1 小时」第 1 条想解决的事）。

## 标记重点题与收藏练习

**入口。** 星标按钮在答题页题目卡片**徽标行最右侧**（题型 / 章节徽标之后，靠右对齐），40×40、原生 `<button>`、可用键盘 Tab 聚焦。空心 `☆` 是没标，实心 `★`（强调色）是已标，`aria-pressed` 跟着状态走，`aria-label` 在「标记重点题 / 取消标记」之间切换。点它**不会**选选项、不会提交、不会打断答题，页面停在原题。结果页的错题行 / 未作答行右侧也各有一个同样的星标（在「反馈」「查看」左边），交完卷顺手标重点。

**存储（唯一新增的键）。** `quiz:stars`，走 `js/core/store.js`，扁平一张表：

```json
{"stars": {"web:31": 1760000000000, "java:7": 1760000001200}}
```

键是 `<题库 key>:<题号>`，值是标记时间戳。**收藏是题目级的**，所以普通轮、重练轮、错题练习、收藏练习里看到的是同一颗星；标记只跟题目走，不跟轮次走，也不会改动任何一轮的作答或成绩。坏数据（不是合法 JSON、版本不符、值不是正数时间戳、键里没有 `:`）一律当成空表，不报错、不白屏。除这个键以外没有新增任何存储。

**收藏练习。** 首页卡片下 `收藏练习（n）`，n=0 时置灰 + 小字「还没有标记的题」。按下按**题库原序**（不是收藏时间序）把该题库收藏的题拼成一轮，其余与普通练习完全一样：可作答、可交卷、出结果、能再练一遍，练习记录里显示为「**收藏练习**」，进度键是 `quiz:pool:<题库>:stars`，快照带 `origin: 'stars'`。

**为什么按题库原序。** 收藏的时间序对「刷重点」没有意义；按题序走，你能顺着章节推进，也方便和错题本对照。收藏数很少时（比如 2 题）一轮就很短，这是预期行为。

## 反馈与维护日志

题库是多人整理的，题干、选项、答案、解析都可能出错，所以每道题都能就地反馈。纯静态模式下 Recall 不联网（无后端、无接口、无 CDN），反馈**只存在这台设备的浏览器里**，上报靠一键复制那段文字；如果起了可选的服务端（见「两种运行模式」），提交成功就直接写进本机 SQLite、提示「已上报」，失败或探不到服务端则照旧进本机反馈箱。这是明确的取舍，理由见「关键设计」第 6 条。

**入口。** 答题页题目卡片右下角有「反馈」小按钮（图标 + 小字，不抢「提交 / 上一题 / 下一题」）；结果页只在**错题行**右侧提供（未作答的题先去做）。点开后是反馈面板，自动带好题库、题号、题型、题干前 40 字、我的选择 / 当前答案、页面与时间，不需要手打定位信息；问题类型五选一（题干 / 选项 / 答案 / 解析有误 + 其他），备注选填、最多 200 字。关闭方式：点遮罩或按 `Esc`，都不会动答题进度。

**反馈箱。** 题库列表页底部「反馈箱（n）」，n 是还没上报的条数（没有就不带数字）。行内「复制」「删除」，「全部复制」按条拼接一并标记「已复制」，「清空反馈箱」要二次确认。数据在 `quiz:feedback`，仍然只通过 `js/core/store.js` 读写。

**复制出来的格式**（`js/ui/copy.js` 的 `FB_TEXT()` 是唯一实现，格式固定，维护者拿到就能定位）：

```
【题库纠错】Web前端题库 · 第 80 题（单选）
类型：答案有误
我的选择：B ｜ 当前答案：B
题干：在 JavaScript 中，用于向数组开头添加元素的正确方法是（　）
说明：（可选，没填就是这一行原样）
页面：答题页 ｜ 时间：2026-10-17 14:02
```

**维护日志。** 题库列表底部「维护日志」，按日期倒序，每条带类型标签（题库修正 / 功能更新 / 样式调整）。数据是 `js/data/changelog.js` 里人工维护的静态数组——**不从** `docs/数据质量报告.md` 自动读：那份报告是给维护者定位题目用的，措辞与粒度都不适合对外。改日志就改这个文件，新条目写在最前面。

**三个真实的翻车与修复**（原文都留在单独提交的会话记录包里，没有删）：

1. **题干 / 选项的空白结构被压缩。** 第一版转换器对文本做了归一化，结果 Java 有 24 道题的代码块缩进全丢、渲染出来代码顶格；Java #219（唯一的材料题）段间空行被吃掉，产出 1875 字符 vs 原文 2058 字符，多段材料会糊成一大段。修复：题干 / 选项 / 解析**只 trim 首尾**，内部换行与行首缩进原样保留；同时加了一道防回归的逐题逐字段保真自检（现在每次运行都打印「339/339 无意外差异」）。
2. **题型徽标出现空药丸。** 数据里 `type` 是 `single` / `multiple` / `judge`，视图直接取中文名，遇到没映射的值就渲染出一个空的圆角壳。修复：`js/ui/copy.js` 集中 `TYPE_CN` 与 `TYPE_NAME(type)`，未知类型回退成原字符串而不是空字符串，e2e 里补了「徽标文字只出现三种题型名」的全量扫描断言。
3. **e2e 断言读整页文本，导致自证假通过。** 早期断言用 `document.body.textContent` 判断「页面上出现了某句话」，可 `tools/e2e.html` 自己的 `<script>` 也在 body 里，断言文案本身被当成了页面文字——写什么都能过。修复：页面正文只取 `#app` 这一个容器（`appText()`），断言日志单独输出到结果区。这条让我后面所有断言都改成「量具体元素」而不是「搜整页文字」。

## 如果再给 1 小时，最想完善什么

1. **错题本加「已掌握」标记**：现在错过的题会一直留在错题本里，想能标「已掌握」并移出，避免越积越多；最好再按错误次数排序，考前先刷最常错的。没做是因为错题本是只读派生视图，加状态要同时改存储、去重口径与「错题练习」的取题入口，一小时只能做出半套。
2. 深色模式下的小字对比度：深色是后加的，浅色那套调得久，深色下有几处辅助文字（题号、时间、说明）偏灰。想逐页量一遍对比度，再把「定时切换」补上（跟随系统已经有了）。没做是因为量对比度要截图、取色、改一处再复核，一小时只够量完一半页面。
3. 按章节的正确率：结果页现在只有整轮正确率，两百多题刷下来，其实更想知道「哪一章最弱」。想按章节拆开统计，并在首页给一个「去刷最弱的一章」的入口。没做是因为它要改统计口径（现在整轮只有一个分母）并动结果页结构，容易把现有 e2e 断言打散。
4. **支持用户导入自己的题库**：只收结构化的 Markdown / JSON，导入时逐题校验并报出错行号；受本地存储限制，先限 200 题、1MB，不收图片；判分和练习完全复用现有机制，只把题目来源从常量换成存储。不做 PDF / Word / 图片的「智能识别」——不可控，错了还找不到原因。没做是因为导入还要新增校验、错误行号、条数与体积上限和空态，边界多，不想交一个半成品。
5. **开屏动画**：进入时 200ms 淡入的品牌名，只首次加载出现，`prefers-reduced-motion` 时直接跳过。没做的原因是它会拖慢「打开就用」的第一印象，而且新拟物本身偏安静，多余动效容易显廉价。
6. **答题卡边框完善**：当前题的紫色焦点环在网格滚动容器边缘会被裁掉一角（外层是 overflow-y:auto 且没留内边距）。改成内描边（`box-shadow: inset 0 0 0 2px`）或给网格容器加内边距，保证任何位置的格子边框都完整。

## 已知限制

- **纯静态，无跨设备同步**：进度、轮次、反馈、主题、收藏都存在本机 localStorage（`quiz:progress:*`、`quiz:rounds:*`、`quiz:practice:*`、`quiz:pool:*`、`quiz:stars`、`quiz:feedback`、`quiz:theme`、`quiz:app`），换浏览器或清缓存就没了；可选服务端只落反馈，轮次同步仍是设计。
- **反馈默认不自动上报**：纯静态模式下没有后端，靠使用者复制粘贴交给维护者；只有起了可选的服务端（`node server\server.mjs`）才会在提交时自动入库（取舍见「关键设计」第 6 条）。
- **无多用户 / 无账号**：一台设备一份数据，没有登录、没有权限。
- **深色下新拟物层次天生弱**：亮影只能比底色亮一档（再亮就像发光描边），凸起的立体感不如浅色明显。
- **没有自定义快捷键**：只有 Tab / Enter / 空格 / `Esc` 这套浏览器原生操作，没有字母或数字直接选题。
- **`tools/e2e-narrow.html` 需要 http 服务**：`file://` 下 iframe 跨域跑不起来。
- **唯一的字面颜色例外**：`index.html` 与 `style-preview.html` 的 `<meta name="theme-color" content="#e0e5ec">`。meta 不能用 CSS 变量，只能写字面值，但它由 `js/core/theme.js` 在切换主题时同步更新；除这一处以外，颜色与阴影全部在 `css/styles.css` 的变量里，交付目录中的页面与脚本零硬编码。
- **测验记录里的早期会话有缺口**：单独提交的会话记录包里，`00-总记录.md` 的「覆盖率说明」列出了 11:09:30→11:14:29、11:36:36→11:42:40 两处约 5 分钟的空档，以及「归档会话那段以我自己手动转录为准」等 7 条已知缺口，没有补写。
